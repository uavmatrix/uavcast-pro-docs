Нет телеметрии в QGroundControl или Mission Planner

UAVcast-Pro показывает полётный контроллер как Подключено, но QGroundControl сообщает Waiting for vehicle connection, а Mission Planner выдаёт таймаут с No heartbeat packets received. Дрон слышит полётный контроллер; телеметрия просто не доходит до вашей наземной станции.

Если сам UAVcast-Pro показывает No heartbeat, сначала исправьте это: Нет MAVLink heartbeat.

Проверка 1: отправляется ли телеметрия?​

  1. Откройте Панель управления и прочитайте строку Ground station в карточке состояния.
    • None set up: пункта назначения нет. Добавьте его на шаге 2.
    • Not sending: пункт назначения есть, но ничего не отправляется.
    • Sending to … · n packets/s: телеметрия покидает дрон. Перейдите к проверке 2.
  2. Перейдите в Наземные станции. Нажмите Добавить пункт назначения, если список пуст.
  3. На карточке вашего компьютера включите Включить конечную точку и Включить телеметрию. И видео, и телеметрия по умолчанию выключены для нового пункта назначения.
  4. Введите IPv4-адрес компьютера в поле IP-адрес или хост назначения и оставьте Порт телеметрии равным 14550.
Недопустимые адреса пропускаются

UAVcast-Pro принимает только адреса IPv4, например 192.168.1.10. Если вы попытаетесь сохранить имя хоста, появится сообщение Enter a valid IPv4 address, for example 192.168.1.10. Отсутствующий или недопустимый адрес пропускается маршрутизатором телеметрии, а Connection check на странице «Полётный контроллер» выводит его в списке.

Проверка 2: убедитесь, что наземная станция слушает​

UAVcast-Pro отправляет MAVLink по UDP на заданный адрес и порт. Наземная станция должна слушать этот порт.

  • QGroundControl по умолчанию слушает UDP 14550. Если вы изменили Порт телеметрии, добавьте UDP comm link на том же порту в Application Settings → Comm Links.
  • Mission Planner: выберите UDP в выпадающем списке подключения в правом верхнем углу, нажмите Connect и подтвердите порт 14550.
  • Слушать порт может только одна программа. Закройте MAVProxy, второй экземпляр QGroundControl или другой инструмент, который может занимать 14550.
  • Разрешите входящий UDP 14550 в брандмауэре. Команды описаны в Нет видео, проверка 3.

Проверка 3: используйте адрес VPN через сотовую сеть​

Через 4G дрон не может достучаться до локального адреса вроде 192.168.1.20. Укажите VPN-адрес вашего компьютера (Fleet Manager VPN, Tailscale или ZeroTier) в поле IP-адрес или хост назначения.

С компьютера выполните ping до VPN-адреса дрона. Если ping не проходит, проблема в VPN: см. VPN подключён, но до дрона нет доступа.

Проверка 4: TCP 5760 больше не работает​

Начиная с v6.5.0 маршрутизатор телеметрии не принимает TCP-подключения на порту 5760, поэтому данные получают только те наземные станции, которые вы добавили и включили. Если раньше вы подключали Mission Planner по TCP 5760, добавьте компьютер как пункт назначения и подключайтесь по UDP.

Проверка 5: команды игнорируются​

Если телеметрия отображается, но взведение, смена режимов или загрузка миссий ничего не делают, проверьте Read Only для этого пункта назначения. Read Only блокирует всё, что может изменить аппарат (команды, смену режимов, запись параметров и миссий), поэтому наземная станция может только наблюдать. Это действует начиная с UAVcast-Pro 6.5.3; в более ранних версиях Read Only не блокирует запись параметров. Некоторые наземные станции показывают предупреждения в этом режиме, потому что часть их запросов остаётся без ответа.

Всё ещё ничего?​

Скачайте журналы с выбранным Mavlink Manager и отправьте их на support@uavmatrix.com. Укажите, какую наземную станцию вы используете, и её IP-адрес.
