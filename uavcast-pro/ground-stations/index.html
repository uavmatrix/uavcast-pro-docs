Ground control stations

A destination tells UAVcast-Pro where to send telemetry and video. Each one is an IP address plus a telemetry port and a video port. UAVcast-Pro sends to every enabled destination at the same time over UDP, so Mission Planner on one laptop and QGroundControl on a tablet can both receive the drone. Open Ground Control Stations in the sidebar.

Add a destination​

  1. Select Add Destination. A new card appears. (A fresh install already has one empty card.)
  2. Enter a Name, for example Pilot laptop.
  3. Enter the ground station computer's IPv4 address in Destination IP or Host and press Enter. A green check means it's saved.
  4. Check Telemetry Port (default 14550) and Video Port (default 5600). Use the ports your ground station listens on.
  5. Turn on Enable Telemetry and, if you want video, Enable Video.

Every field saves when you press Enter or leave it. There is no Save button. Telemetry routing picks up the change within a few seconds.

Use an IPv4 address, not a hostname

Despite the label Destination IP or Host, UAVcast-Pro only accepts an IPv4 address such as 192.168.1.20 or a VPN address such as 10.147.17.5. Hostnames are rejected with Enter a valid IPv4 address, for example 192.168.1.10.

Which IP address to use​

Where the ground station isUse
Same Wi-Fi or Ethernet network as the droneThe ground station's LAN address, for example 192.168.1.20.
Anywhere, over 4G/LTEThe ground station's VPN address (ZeroTier, Tailscale or Fleet Manager). See VPN.
Several computersOne destination per computer.

The ground station receives telemetry but can't change anything on the vehicle: commands, arming, mode changes, parameter writes, mission writes, RC override and manual control from it are blocked. This applies from UAVcast-Pro 6.5.3; on earlier versions, Read Only does not block parameter writes.

Audio, when you turn on Send audio to ground stations on the Camera page, goes to every destination that receives video, on Video Port + 2 (for example 5602). See Audio.

So each destination occupies three video-side ports: Video Port, + 1 (camera 2) and + 2 (audio). If two destinations point at the same computer, space their video ports 3 apart, for example 5600 and 5603. See Two stations on one computer.

What the drone sends​

StreamFormatPort on the ground station
TelemetryMAVLink over UDPTelemetry Port (default 14550)
Camera 1 videoH.264 in RTP, payload type 96, over UDPVideo Port (default 5600)
Camera 2 video (dual stream)H.264 in RTP, payload type 96, over UDPVideo Port (Camera 2) (default Video Port + 1, 5601)
Audio (optional)Opus in RTP, payload type 97, 48 kHz, over UDPVideo Port + 2 (5602)

The drone pushes every stream to the destination. Nothing needs to connect to the drone, but the ground station's firewall must let the UDP packets in.

Several ground stations​

Add one destination per computer. If two ground stations run on the same computer (for example QGroundControl and a logging tool), give them different telemetry ports, such as 14550 and 14551, and set each application to its port.

Use Read Only for observers, payload operators or a second screen: they see everything but can't command the vehicle.

Destinations from Fleet Manager​

When the drone is paired with Fleet Manager and you create a stream binding there, Fleet Manager adds the destination for you. These cards show a cloud icon (Managed by Fleet Manager). Change them in Fleet Manager rather than here. See Pair with Fleet Manager.

Check that data is flowing​

  • The Dashboard Ground station row reads Sending · 16 packets/s or Sending to 2 · … packets/s.
  • Flight Controller → Connection → Connection check lists each destination with its packet rate.
  • 1 set up · waiting for flight controller means the destination is fine but no telemetry comes from the flight controller yet.

Read-only users see this page but can't change it.

Troubleshooting​

  • No telemetry in the ground station
  • No video in QGroundControl or Mission Planner
