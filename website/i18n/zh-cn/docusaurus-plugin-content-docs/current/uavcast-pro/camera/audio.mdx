# 音频 {/* #audio */}

UAVcast-Pro 可以添加来自 USB 麦克风或 USB 摄像头内置麦克风的声音。音频以 Opus 编码，几乎不占用 CPU 和带宽。音频始终会在实时预览中播放，您也可以将其作为单独的 RTP 流发送到地面站。该功能位于 **摄像头 → 摄像头设置** 中的 **音频** 卡片。

## 启用音频 {/* #turn-on-audio */}

<Steps>

1. 插入 USB 麦克风，或使用带内置麦克风的网络摄像头。
2. 在 **摄像头 → 摄像头设置** 中，启用 **音频**。
3. 将 **音频设备** 保持为 **自动（如有摄像头麦克风则使用）**，或选择一个设备。如果没有麦克风，可使用 **测试音（无需麦克风）** 来测试音频通路。
4. 观察指示器。显示 **音频实时** 且电平表在移动，表示已成功采集到声音。
5. 在 **实时预览** 中取消播放器静音。浏览器默认以静音状态启动预览。

</Steps>

<Screenshot id="uavcast-pro/camera--audio" alt="摄像头页面的音频卡片，音频开关处于关闭状态，状态显示为音频已关闭" caption="摄像头 → 音频，已关闭。启用后即可选择麦克风和比特率。" />

麦克风故障绝不会中断视频。指示器会改为显示 **音频错误** 及其原因。

## 将音频发送到地面站 {/* #send-audio-to-ground-stations */}

启用 **将音频发送到地面站**。随后，UAVcast-Pro 会向每个接收视频的地面站发送单独的 RTP/Opus 流，端口为该目标地址的 **视频端口 + 2**。使用默认视频端口时，端口为 `5602`。因此，同一台计算机上的两个目标地址，其视频端口至少需要相隔 3，例如 `5600` 和 `5603`。

QGroundControl 和 Mission Planner 会忽略音频。请使用 GStreamer 播放：

```bash title="地面站上"
gst-launch-1.0 udpsrc port=5602 caps="application/x-rtp, media=(string)audio, clock-rate=(int)48000, encoding-name=(string)OPUS, payload=(int)97" ! rtpopusdepay ! opusdec ! audioconvert ! autoaudiosink
```

该流为 48 kHz 的 Opus 格式，RTP 负载类型为 97。VLC 可以使用描述这些参数的 SDP 文件来播放该流。

## 设置参考 {/* #settings-reference */}

| 设置 | 默认值 | 可选值 | 说明 |
|---|---|---|---|
| **音频** | 禁用 | 启用、禁用 | 更改任何音频设置都会重启摄像头服务。 |
| **音频设备** | **自动（如有摄像头麦克风则使用）** | 自动、已检测到的采集设备、**测试音（无需麦克风）** | 已保存但被拔出的设备会显示为 *（未连接）*。 |
| **比特率** | `64 kbps` | 24、32、48、64、96、128 kbps | 32–64 kbps 足以满足语音和引擎噪声的需要。 |
| **将音频发送到地面站** | 禁用 | 启用、禁用 | 将 RTP/Opus 发送到每个已启用视频的目标地址的视频端口 + 2。 |

## 故障排除 {/* #troubleshooting */}

- *未找到音频采集设备*：请插入 USB 麦克风或带内置麦克风的摄像头。在无人机上，运行 `arecord -l` 可列出采集设备。
- **无信号**：设备已打开但没有声音。请检查麦克风的静音开关，或尝试 **测试音**。
- 预览中有音频，但地面站没有：请确认 **将音频发送到地面站** 已启用，目标地址已启用 **启用视频**，并且接收端监听的是视频端口 + 2。
