# Передача на несколько наземных станций {/* #stream-to-multiple-ground-stations */}

Один дрон, несколько экранов: пилот в Mission Planner, оператор полезной нагрузки в QGroundControl, руководитель, который наблюдает из офиса. UAVcast-Pro отправляет телеметрию и видео каждому добавленному пункту назначения, и у каждого из них свои переключатели.

## Как это работает {/* #how-it-works */}

Каждая запись в разделе **Наземные станции** — это один пункт назначения: IPv4-адрес, порт телеметрии и порт видео. UAVcast-Pro отправляет:

- телеметрию MAVLink по UDP на **Порт телеметрии** (по умолчанию 14550), если включена опция **Включить телеметрию**;
- видео H.264 по RTP/UDP на **Порт видео** (по умолчанию 5600), если включена опция **Включить видео**;
- ничего, если опция **Включить конечную точку** выключена.

Команды от каждого пункта назначения доходят до полётного контроллера, если только этот пункт не помечен как **Read Only**.

## 1. Добавьте пункт назначения для каждой станции {/* #1-add-a-destination-per-station */}

<Steps>

1. Откройте **Наземные станции** и нажмите **Добавить пункт назначения** для каждой станции.
2. Задайте каждому **Название**, которое вы узнаете в поле, например *Пилот – Mission Planner* и *Полезная нагрузка – QGC*.
3. Введите IPv4-адрес каждого компьютера в поле **IP-адрес или хост назначения**. Через 4G используйте адреса VPN.
4. Включите **Включить телеметрию** и **Включить видео** там, где это нужно. Станция, которой нужна только телеметрия, экономит трафик, если видео выключено.

</Steps>

## 2. Сделайте наблюдателей читающими {/* #2-make-observers-read-only */}

Тем, кто должен наблюдать, но не управлять, включите **Read Only** для их пункта назначения. Станция по-прежнему получает телеметрию в реальном времени, но не может ничего изменить на аппарате: команды, смену режимов, взведение, запись параметров, запись миссии и RC-переопределения от неё блокируются. Это действует начиная с UAVcast-Pro 6.5.3; в более ранних версиях Read Only не блокирует запись параметров. Программы наземной станции могут показывать предупреждения в этом режиме, потому что часть их запросов (например, загрузка параметров или миссии) остаётся без ответа.

:::warning Два пилота, один дрон
Без режима Read Only любая станция может отдавать команды дрону. Договоритесь, кто управляет, и переведите все остальные станции в режим только для чтения.
:::

## 3. Две станции на одном компьютере {/* #3-two-stations-on-one-computer */}

Две программы на одном компьютере не могут слушать один и тот же порт. Добавьте два пункта назначения с одинаковым IP-адресом и разными портами, например:

| Пункт назначения | Порт телеметрии | Порт видео |
|---|---|---|
| Mission Planner | 14550 | 5600 |
| QGroundControl | 14551 | 5603 |

Затем настройте вторую программу на прослушивание этих портов (в QGroundControl добавьте UDP-канал связи (comm link) на 14551 и задайте UDP-порт видео 5603).

Разносите видеопорты на **3** (5600, 5603, 5606 …). Каждый пункт назначения использует свой порт видео, плюс порт видео + 1 для второй камеры в [двойном потоке](./dual-camera-rc-switching.mdx) и порт видео + 2 для [аудио](../uavcast-pro/camera/audio.mdx). Порты, расположенные ближе, конфликтуют, как только вы включаете двойной поток или аудио.

## 4. Учитывайте восходящий канал {/* #4-mind-the-uplink */}

Каждый пункт назначения с видео получает отдельную копию потока. Три видеопункта по 1500 kbps требуют около 4,5 Мбит/с восходящего канала от дрона. Через 4G отправляйте видео только тем станциям, которым оно нужно, или снизьте битрейт в **Камера → Настройки камеры**. **Панель управления → Сетевой трафик** показывает, что модем реально отправляет.

## 5. Проверьте, что каждая станция получает данные {/* #5-check-that-every-station-gets-data */}

На **Панели управления** строка **Наземная станция** показывает *Отправка на n · x пакетов/с*. **Проверка подключения** в разделе **Полётный контроллер → Подключение** перечисляет каждый выход наземной станции и любой пункт назначения, пропущенный из-за недопустимого адреса.

## С Fleet Manager {/* #with-fleet-manager */}

В Fleet Manager наземные станции входят в VPN организации, а вы подключаете их к дронам с помощью **Stream Bindings** на странице **Network**. Каждый дополнительный дрон, привязанный к той же наземной станции, получает собственный блок портов. См. [Stream bindings](../fleet-manager/network/stream-bindings.mdx).
