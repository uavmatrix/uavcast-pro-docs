# NTRIP / RTK corrections

UAVcast-Pro has a built-in NTRIP client. It connects to an NTRIP v1 or v2 caster over the drone's internet link, receives RTCM3 corrections and passes them to the flight controller as MAVLink `GPS_RTCM_DATA`, the same way Mission Planner's "Inject GPS" does, but from the drone itself. You don't need a ground station or base station on site. Open it under **Flight Controller → NTRIP / RTK**.

## Before you begin

- An RTK-capable GPS on the flight controller: a multi-frequency, carrier-phase receiver such as u-blox F9P, Holybro H-RTK, CUAV C-RTK, Here3+ or Septentrio Mosaic. A standard M8/M10 GPS ignores corrections.
- An account with an NTRIP caster: a national CORS network, a commercial service (Trimble, Hexagon, Topcon and others) or [RTK2go](http://rtk2go.com). You need the host, port, mountpoint, and usually a username and password.
- Internet on the drone and a connected flight controller.

## Set up the NTRIP client

<Steps>

1. Go to **Flight Controller → NTRIP / RTK**.
2. Under **Caster**, enter **Caster host** (for example `ntrip.example.com`) and **Port** (`2101` for most casters).
3. Enter **Username** and **Password** under **Authentication**. Select **Test connection** to check them: *Caster accepted the credentials.*
4. Select **Browse mountpoints**, pick the nearest one in the list and select **Select**. Or type it in **Mountpoint**.
5. If the mountpoint is a VRS or "nearest base" stream (the **NMEA** column says **Required**), keep **Send GGA upstream** on.
6. Turn on **Enable NTRIP client**.

</Steps>

The **Status** card changes to **Streaming corrections** and shows **Total received**, **Throughput**, **Last RTCM frame** and **Recent message types**. With a clear sky, **Flight controller RTK fix** goes from **3D fix** to **RTK Float** and then **RTK Fixed**, usually within a minute or two.

## Settings reference

| Setting | Default | Values | Notes |
|---|---|---|---|
| **Enable NTRIP client** | Off | On, off | |
| **Caster host** | empty | hostname or IP | Required. |
| **Port** | `2101` | 1–65535 | Some TLS casters use 2102 or 443. |
| **Mountpoint** | empty | caster's mountpoint name | Required. Use **Browse mountpoints** to read the caster's sourcetable. |
| **Use TLS (HTTPS)** | Off | On, off | For casters that require TLS. Most public casters use plain TCP. |
| **Username** / **Password** | empty | | Leave empty for anonymous casters. RTK2go wants a real email address as username and no password. |
| **Send GGA upstream** | On | On, off | Sends your position as NMEA `$GPGGA` so VRS and nearest-mountpoint casters can make corrections for your location. |
| **Send interval (seconds)** | `10` | seconds | How often GGA is sent. |
| **Position source** | **Live position from flight controller** | **Live position from flight controller**, **Fixed manual position** | |
| **Latitude** / **Longitude** / **Altitude (m)** | `0` | | Manual position. Also used as a fallback until the flight controller has a GPS fix. |

## Read the GPS quality card

**GPS quality** shows the live fix from the flight controller plus a measurement that doesn't rely on the receiver's own estimate:

- **Fix type** and **Satellites**.
- **Horizontal accuracy** and **Vertical accuracy**: the receiver's own estimate.
- **Position stability (1σ)**: how much the position actually moves while the drone stands still, measured over a short window. It shows **Moving** in flight.
- **Last correction**: time since the last RTCM frame was forwarded. If this keeps growing, corrections have stopped.

If you see **No RTK status from receiver**, the flight controller has never reported RTK status. Usually the GPS isn't RTK-capable. Corrections are still forwarded.

## Over a cellular link

Corrections are small (typically 1 to 5 kbit/s), so they fit easily next to telemetry and video. After a short internet drop the client reconnects within seconds. A silent caster connection is detected within 15 seconds and reopened.

The [Dashboard](../dashboard.mdx) shows the client's state in the **RTK corrections** row.

## Troubleshooting

| Symptom | Check |
|---|---|
| Status **Error**, **Caster response** shows `401` | Wrong username or password, or the account isn't allowed on this mountpoint. |
| **Connected**, but no RTCM frames | The mountpoint needs GGA. Turn on **Send GGA upstream** and make sure the flight controller has a 3D fix, or set a manual position. |
| RTCM arrives, fix stays at **3D fix** | The GPS isn't RTK-capable, or the mountpoint's GNSS systems don't match your receiver. Check the **GNSS** column in the sourcetable. |
| **RTK Float**, never **Fixed** | Base too far away (aim for under 20 to 30 km), poor sky view or multipath. Try a closer mountpoint. |

The **NTRIP service log** at the bottom of the page shows every connect, reconnect and caster reply.
