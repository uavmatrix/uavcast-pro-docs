QGroundControl 或 Mission Planner 沒有視訊

遙測已送達，無人機也顯示在地圖上，但視訊區域仍是黑的，或 QGroundControl 的視訊視窗顯示 WAITING FOR VIDEO。請依序完成以下檢查。多數情況可以由檢查 2 或檢查 3 解決。

您會看到的畫面可能原因從此開始
地面站與 UAVcast-Pro 即時預覽的視訊皆為黑畫面無人機上的攝影機未在執行檢查 1
即時預覽正常，但地面站仍為黑畫面此地面站未開啟啟用視訊，或 IP 錯誤檢查 2
在家中 Wi-Fi 下正常，透過 4G 則為黑畫面目標位址使用本地 IP，而非 VPN IP檢查 2
設定看起來都正確，但在 Windows 上仍為黑畫面防火牆阻擋了連接埠 5600 的傳入 UDP檢查 3
QGroundControl 顯示視訊，但 Mission Planner 沒有Mission Planner 未設定 GStreamer 來源檢查 4

檢查 1：確認攝影機正在無人機上串流​

若無人機沒有產生視訊，任何地面站設定都無法解決問題。

  1. 開啟 UAVcast-Pro 網頁介面，前往攝影機 → 攝影機設定。
  2. 確認啟用攝影機？為是，並在選擇攝影機中選定攝影機。
  3. 確認攝影機正在執行：儀表板的視訊列應顯示執行中。若已停止，請在攝影機頁面按下啟動（攝影機執行中時按鈕會顯示重啟）。
  4. 開啟啟用即時預覽？並查看即時預覽。若看到畫面，表示攝影機正常，可以前往檢查 2。
  5. 若選擇攝影機顯示沒有可用的攝影機，請前往UAVcast-Pro 無法偵測攝影機（CSI 與 USB）。
預覽不是地面站的串流

瀏覽器預覽是透過內建的媒體伺服器（連接埠 8889 上的 WebRTC）。地面站則會透過 UDP 取得獨立的 H.264 串流。預覽正常只能證明攝影機運作正常，無法證明 UDP 串流已經送達您的筆電。

若攝影機頁面上的操作日誌表示攝影機不支援某個解析度，請在解析度中選擇其他值。UAVcast-Pro 會退回到支援的最大尺寸，並記錄它所使用的尺寸。

檢查 2：檢查地面站目標位址​

UAVcast-Pro 只會將視訊傳送到已開啟視訊的目標位址。遙測與視訊各有獨立的開關，而新的目標位址兩者預設皆為關閉。

  1. 前往地面控制站，找到執行地面站軟體那台電腦的卡片。
  2. 確認啟用終端與啟用視訊皆已開啟。
  3. 檢查目標IP或主機。它必須是從無人機角度看到的地面站電腦 IPv4 位址。不接受主機名稱。
  4. 檢查視訊連接埠是否為 5600，或是地面站所監聽的連接埠。
  5. 欄位會在您離開或按下 Enter 時儲存。綠色勾號表示已儲存成功。
透過 4G 飛行？請使用 VPN IP

透過行動網路時，無人機無法連到您筆電的本地位址（例如 192.168.1.20）。請使用您的筆電在 VPN 上取得的位址（Fleet Manager VPN、Tailscale 或 ZeroTier）。在 Windows 上，請執行 ipconfig，並找出 Tailscale 或 ZeroTier 的網路卡。

使用 Fleet Manager 嗎？新增串流綁定時會為您建立目標位址，而同一個地面站上每架額外的無人機都會有各自的連接埠。請檢查綁定上顯示的視訊連接埠，而非 5600。 請參閱串流綁定。

檢查 3：允許 UDP 5600 通過防火牆​

視訊是以傳入的 UDP 流量抵達。在 Windows 上，即使遙測能正常通過（因為地面站已要求開放例外規則），這類流量預設仍會被阻擋。

  • Windows
  • Linux
  • macOS

以系統管理員身分開啟 PowerShell，並執行：

PowerShell (Administrator)PowerShell
New-NetFirewallRule -DisplayName "UAV Video" -Direction Inbound -Protocol UDP -LocalPort 5600 -Action Allow
New-NetFirewallRule -DisplayName "MAVLink Telemetry" -Direction Inbound -Protocol UDP -LocalPort 14550 -Action Allow

ZeroTier 與 Tailscale 網路卡常被歸類為公用網路。以這種方式建立的規則會套用至所有設定檔。

UFWTerminal
sudo ufw allow 5600/udp comment 'UAV Video'
sudo ufw allow 14550/udp comment 'MAVLink Telemetry'

macOS 防火牆會允許您核准的應用程式接收傳入的 UDP。若您在 QGroundControl 首次啟動時按了拒絕，請在系統設定 → 網路 → 防火牆 → 選項中重新允許。

檢查 4：在地面站中設定視訊​

  • QGroundControl
  • Mission Planner
  1. 點擊 Q 圖示，然後點擊 Application Settings。
  2. 開啟視訊設定（Video，舊版則為 General → Video）。
  3. 將來源設為 UDP h.264 Video Stream，並確認 UDP 位址使用連接埠 5600（目前版本為 UDP URL 0.0.0.0:5600，舊版為 UDP Port 5600）。
  4. 返回 Fly 檢視。視訊畫面應在數秒內顯示畫面。

Mission Planner 會在 HUD 中顯示視訊。若仍是黑畫面，請手動設定來源：

  1. 在 HUD 上按右鍵，選擇 Video → Set GStreamer Source。
  2. 貼上以下管線並確認：
Mission Planner GStreamer sourceText
udpsrc port=5600 caps="application/x-rtp, media=video, clock-rate=90000, encoding-name=H264, payload=96" ! rtpjitterbuffer ! rtph264depay ! avdec_h264 ! videoconvert ! video/x-raw,format=BGRA ! appsink name=outsink

檢查 5：不使用地面站測試串流​

此測試會排除地面站軟體。若開啟了一個顯示視訊的視窗，表示無人機、網路與防火牆都正常，問題出在地面站的設定。

Windows, Linux and macOSTerminal
gst-launch-1.0 -v udpsrc port=5600 caps="application/x-rtp, media=(string)video, clock-rate=(int)90000, encoding-name=(string)H264" ! rtpjitterbuffer ! rtph264depay ! avdec_h264 ! videoconvert ! autovideosink sync=false
Windows：請選擇完整安裝

安裝 GStreamer（MSVC 64 位元執行階段）時，請選擇完整。典型安裝會略過 H.264 解碼器，指令會失敗並顯示 no element "avdec_h264"。

在再次開啟地面站之前，請關閉此測試：同一時間只有一個程式能監聽連接埠 5600。逐步的接收端設定說明請見 Mission Planner、QGroundControl，以及 Windows、Linux 或 macOS 上的 GStreamer。

有視訊了，但透過 4G 時卡頓？

請參閱 4G 下視訊卡頓、延遲或灰色色塊。

仍然沒有視訊？​

在日誌清單中選取 Camera Server 的情況下下載日誌，並連同您的 UAVcast-Pro 版本、攝影機型號與您使用的地面站，寄送至 support@uavmatrix.com。
